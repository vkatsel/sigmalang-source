### 3. Що таке `.ebnf` і як він пишеться?
**EBNF (Extended Backus–Naur Form)** — це формальний запис правил синтаксису мови. Це як математична формула мови: все, що дозволяє парсер, описується цими правилами.

Ось базовий синтаксис EBNF:
1. **Правило (продукція)**: `RuleName = Expression ;`
2. **Термінали** (фіксовані токени/слова/емодзі): пишуться в лапках: `"if"`, `"+"`, `"💀"`, `"📦"`
3. **Нетермінали** (інші правила): назви без лапок: `program`, `statement`, `expression`
4. **Вибір (альтернатива)**: вертикальна риска `|`
   ```ebnf
   type = "📦" | "🏛️" | "💡" ;
   ```
5. **Послідовність**: просто йдуть один за одним:
   ```ebnf
   var_decl = type identifier ":=" expr ;
   ```
6. **Опціональність** (0 або 1 раз): у квадратних дужках `[ ... ]`:
   ```ebnf
   if_stmt = "if" expr "{" stmt_list "}" [ "else" "{" stmt_list "}" ] ;
   ```
7. **Повторення**:
   - `{ ... }` — повторення 0 або більше разів (як `*` у regex).
   - Або якщо 1 і більше: `statement { statement }` (або `statement+`).

```ebnf
(* Declarations: constants (canon), mutable (yap), immutable (canonmaxing) *)
decl         ::= var_kind type ident ":=" expr ;
var_kind     ::= "canon" | "yap" | "canonmaxing" ;

type         ::= i32_type | i64_type | bool_type ;
i32_type     ::= "npc"   | "👶" ;
i64_type     ::= "sigma" | "🗿" ;
bool_type    ::= "take"  | "💡" ;

(* Assignment: only allowed for mutable (yap) variables *)
assign       ::= ident ( ":=" | "👈🏻" ) expr ;

(* If-Else block: requires at least one statement in each block *)
if_stmt      ::= "is_this_real" expr "{" statement { statement } "}" [ "nah" "{" statement { statement } "}" ] ;

exit_stmt    ::= "exit" factor ;

(* Expressions *)
expr         ::= arith [ ( "==" | "!=" | "🤝" | "💔" ) arith ] ;

arith        ::= term { ( "+" | "-" ) term } ;

term         ::= factor { "*" factor } ;

factor       ::= number | "hot" | "cringe" | ident | "(" expr ")" ;
```

### Аналіз граматики на масштабованість, консистентність та зручність

Я провів ретельний компіляторний аудит поточної граматики:

#### 1. Детермінованість та однозначність (LL(1) сумісність) — ✅ Відмінно
- **Оператори (Statements):** Множини перших токенів (`FIRST`) для кожного типу оператора взагалі не перетинаються:
  - `decl` починається з `var_kind` (`canon`, `yap`, `canonmaxing`).
  - `assign` починається з `ident`.
  - `if_stmt` починається з `"is_this_real"`.
  - `exit_stmt` починається з `"exit"`.
- Це означає, що рекурсивний спуск (`peek()` / `eat()`) писатиметься максимально просто: за першим же токеном парсер на 100% знає, яку функцію викликати, без бектрекінгу.

#### 2. Пріоритет та асоціативність операторів — ✅ Відмінно
- Граматика строго розбита на шари:
  $$\text{expr (порівняння)} \rightarrow \text{arith (+, -)} \rightarrow \text{term (*)} \rightarrow \text{factor (число, bool, змінна, дужки)}$$
- Завдяки цьому правило `a + b * c` природно обчислює множення раніше, а `x + 1 == y` порівнює результат після додавання.
- Правило `expr ::= arith [ comp_op arith ]` дозволяє **не більше одного порівняння у виразі**, що захищає від помилок подвійного порівняння.

#### 3. Блоки умовних переходів — ✅ Відмінно
- `statement { statement }` всередині `{ ... }` гарантує обов'язкову наявність хоча б одного оператора у блоці, як вимагає ТЗ (`stmt+`).

### Кілька рекомендацій для ще більшої зручності та масштабованості:

1. **Дозволити `👈🏻` в ініціалізації (`decl`):**
   Зараз в оголошенні змінної стоїть лише `:=`:
   ```ebnf
   decl ::= var_kind type ident ":=" expr ;
   ```
   Якщо дозволити й емодзі:
   ```ebnf
   decl ::= var_kind type ident ( ":=" | "👈🏻" ) expr ;
   ```
   тоді код на кшталт `yap npc score 👈🏻 100` виглядатиме дуже органічно й консистентно з `assign`.

2. **Від'ємні числа та перевірка переповнення (Type Overflow):**
   У ТЗ є окрема вимога: *«type overflow checks»* (перевірка, що число вміщується в `i32` або `i64`).
   Мінімальні значення для знакових чисел від'ємні (наприклад, для 32-біт це $-2^{31} = -2147483648$).
   Якщо ми додамо унарний мінус у `factor`:
   ```ebnf
   factor ::= [ "-" ] number | bool_lit | ident | "(" expr ")" ;
   ```
   це дозволить писати від'ємні числа прямо в коді (`-42`, `-2147483648`) та повноцінно протестувати переповнення як згори, так і знизу.

3. **Коментарі в коді:**
   У граматиці вони не зазначаються, але в лексері ми одразу закладемо ігнорування коментарів (наприклад, рядкових `// ...` або `# ...`), щоб у тестових файлах можна було залишати пояснення.
